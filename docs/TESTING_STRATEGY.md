# Testing strategy — evidence correctness before code coverage

**Status: local unit/property/contract/CLI/E2E/resource/package tests implemented; hosted Ubuntu 24.04/macOS 15 Intel matrix passed.** Testing targets *prevention of false clean decisions*, not just happy-path parsing. Normal suite must never unpickle or load arbitrary models. P2 guest tests are separate, opt-in, never on typical CI.

```text
  scanner_stub/exit_0_without_per_file_proof.json
  scanner_stub/exit_1_findings.json
  scanner_stub/exit_2_error.txt
  scanner_stub/exit_3_no_supported.txt
  scanner_stub/exit_4_usage.txt
  e2e/complete_safe_fixture/
  e2e/missing_mandatory_fixture/
```

Fixtures generated by stdlib and limited to small sizes (suggest <64 KiB each); include expected file SHA-256 and license of test input. No real malicious pickle payloads committed for routine tests. Use inert stand-in structures/mocked scan outputs to exercise failures. Test realistic attack artifacts only in research-controlled environment and avoid redistributing exploit samples accidentally.

## Required scenario oracle table

| Scenario | Required check | Expected policy default |
|---|---|---|
| Bounded clean supported input, every mandatory check complete | COMPLETE, NO_FINDINGS | APPROVE (scoped) |
| Safe artifact but requires named mandatory use condition | COMPLETE with controllable rule | CONTROLS |
| Explicit prohibited repository source confirmed by inventory/policy | verified prohibition | BLOCK |
| ModelScan exits 2 / crashes / times out | FAILED | INSUFFICIENT |
| Scanner exits 0 but missing per-file proof | INCONCLUSIVE | INSUFFICIENT if required |
| Unknown required format | UNSUPPORTED | INSUFFICIENT |
| Inconsistent source licenses | conflict record | INSUFFICIENT if license clarity mandatory |
| Identity changes during scan | FAILED identity | INSUFFICIENT |
| Unreadable input or reports inside input | invalid input | CLI 40 |
| Reporter crashed before valid decision | orchestration error | CLI 50 |
| Interrupted scan | no approval | CLI 130 |

## Property-based invariants

1. A required check with status other than COMPLETE cannot change INSUFFICIENT to APPROVE or CONTROLS without a separately evidenced BLOCK.
2. Adding a new unassessed required file cannot improve decision from INSUFFICIENT to APPROVE.
3. Reordering raw checks/claims cannot alter semantic policy outcome.
4. Manifest digest changes when any file byte/path/size changes; relative enumeration order does not affect it.
5. An unknown enum, duplicate canonical file ID, incompatible tool version or empty findings on FAILED cannot count as complete.
6. Golden JSON serialization has stable key order/semantic digest; timestamps/runs are explicitly excluded.

## Coverage metrics and gates

Initial targets **proposals**: ≥90% branch coverage in policy/coverage/identity modules; all documented fail-open regression fixtures passed; 100% P0 requirement-to-test linkage. General project-wide percentage only informational; a 100% test-line measure cannot establish real-world model security. CI should run unit/integration and safe E2E on Linux/macOS; behavior tests P2 excluded by default.

## Regression and error triage

Every confirmed security failure: create harmless reproducer → assert fails on previous behavior → implement fix → review snapshot/normalizer/policy layers → run full suite → assess older reports' trust. Fail-closed bugs block release. Record actual commands/results in `PROGRESS.md`; no claim about unexecuted tests.

## PH-05 executed policy cases

`tests/test_policy.py` includes the property cases here (no separate `test_policy_props.py` is needed yet). The exhaustive loop evaluates all 1,296 four-check status combinations under plain and controlled policies; any mandatory gap prevents APPROVE/CONTROLS. Other cases cover independent bans, missing ban proof, mislabeled integrity conflicts, empty/model-free/unknown inputs, row tampering, source identity, unresolved scanner labels, claim conflicts, explicit optional gaps and deterministic permutations. `tests/test_policy_config.py` covers bounded TOML, version/unknown/contradictory rules, control ownership, safe file reads, drift, hash invariance, schemas and CLI 0/40 paths. Final PH-05 suite: 287 tests on macOS. This is not Linux CI, full scan E2E or release acceptance.

## T-OSV-01 implemented supplement cases

`tests/test_advisories.py` covers exact/no-match/withdrawn records, freshness boundary and future data, missing/partial/paginated queries, unsupported ranges/conditions/ecosystems/schema, unpinned/duplicate declarations, malformed/oversized/linked/special files, identity drift, no network, deterministic identity and CLI 0/30/40 behavior. `tests/test_release.py` also installs and runs the supplement with socket connections denied, verifying the original scan report is unchanged. This tests supplied-record matching, not live vulnerability detection efficacy.

## T-BENCH-01 local engineering evidence

`test_benchmark_manifest.py`: 28 cases cover deterministic identity/materialization, modes, alternative byte methods, bad inputs, links/limits, tampered paths/hashes/eligibility/labels and forbidden review/holdout promotion. `test_benchmark_metrics.py`: 23 cases separate NOT_APPLICABLE/unavailable from misses, keep zero-denominator rates null, reject contradictory/duplicate identities, validate complete accounting and fail without a completion marker on report failure/interruption. A fresh installed-package test runs the pilot offline with unavailable scanner injection. Real ModelScan development evidence is retained separately; no ordinary CI malicious execution or independent adjudication is claimed.
