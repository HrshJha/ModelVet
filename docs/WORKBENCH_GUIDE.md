# ModelVet Workbench — local preview

A private browser workspace for the existing static assessment engine. It does not load models, run repository code, repair artifacts or authenticate metadata. A finished scan can produce any admission decision. This is the Mac-first local preview; benchmark/loader research is deferred. Internal engineering review and the Mac release contract apply.

## Launch from this checkout

Use Python 3.12 and the pinned uv version. Node is unnecessary to launch the checked-in compiled application.

```sh
uv sync --locked --extra ui
uv run --extra ui modelvet ui --models-root /absolute/path/to/models
```

Choose a root containing only the model folders you intend to expose. The workspace defaults to `~/.local/state/modelvet/workbench` and must be outside the models root. Both ancestor directions and linked/unsafe paths are rejected. The folder browser cannot navigate above the selected root. Filesystem rejection remains best effort against concurrent changes.

For a separate workspace or manual browser handoff:

```sh
uv run --extra ui modelvet ui --models-root /absolute/path/to/models \
  --workspace /separate/private/modelvet-workspace --port 0 --no-browser
```

The server binds only `127.0.0.1`, with an OS-assigned port by default. Open the private one-use launch link printed with `--no-browser`. Treat that terminal output as a local capability; do not share it. The fragment is removed immediately and exchanged for an HttpOnly session cookie. Keep the browser on the exact numeric-loopback address. Other hosts, origins, replayed launch tokens and unauthenticated API calls are rejected. Existing authenticated tabs can refresh; a different browser needs a fresh launch after stopping the server. There is no remote account or internet asset request.

### Installed wheel

Build and install the local candidate with its optional extra; substitute the actual wheel path:

```sh
uv build
uv venv --python 3.12 /separate/modelvet-venv
uv pip install --python /separate/modelvet-venv/bin/python 'dist/modelvet-0.1.0-py3-none-any.whl[ui]'
/separate/modelvet-venv/bin/modelvet ui --models-root /absolute/path/to/models
```

Python UI dependencies must already be cached for an offline installation. Runtime assets, generated contract and third-party notices ship in the package. No frontend development server or Node runtime is needed. Offline installation/network denial acceptance uses a disposable environment, not a product-wide scanner network sandbox.

## Complete demonstration workflow

1. Open Overview. The four **Synthetic demonstrations** show APPROVE, CONTROLS, BLOCK and INSUFFICIENT. They are frozen real static reports from inert generated bytes, not trained weights. They never enter saved history. Demonstration attachment verification is disabled because no live raw workspace is supplied.
2. Create a new inert fixture under a new root; existing paths are refused:

   ```sh
   mkdir /tmp/modelvet-demo-models
   uv run python examples/create_fixture.py /tmp/modelvet-demo-models/candidate --variant unknown
   uv run --extra ui modelvet ui --models-root /tmp/modelvet-demo-models
   ```

3. Choose **New scan → Browse folders → candidate**. Keep the default policy. Resource settings can lower the engine ceilings. Start the scan; progress shows observed stages and elapsed time, not a guessed percentage. Only one scan is accepted at a time.
4. The unknown `opaque.bin` produces INSUFFICIENT. Open the file/check matrix, filter unresolved files, and inspect its classification evidence and rule/check IDs. Review declarations, conflicts and deterministic next steps. Missing evidence never becomes approval through a completed job or an attachment check.
5. For this explicitly generated demonstration only, remove the known opaque fixture file yourself (`/tmp/modelvet-demo-models/candidate/opaque.bin`), then select **New scan** from the report. Confirm the policy and rerun. This is an intentional change to synthetic test data, not advice to delete unknown files from a real model.
6. Open **Compare**, select the two saved runs and inspect artifact/check/decision differences. Paths are hidden unless explicitly revealed. Original report admission is never recomputed by comparison.
7. Download JSON or escaped Markdown. Import the downloaded JSON through History. Its original bytes are preserved and its schema/digest revalidated. Importing JSON does not provide declared raw attachments or prove the author's claims. Verify reports in their original workspace with their original attachments; the browser does not accept arbitrary raw-file paths.

The supported safetensors fixture can APPROVE without ModelScan because no serialized format requires it. `APPROVE` applies only to configured predicates on the recorded artifact and policy. `CONTROLS` requires named owners/conditions to be enforced outside ModelVet. `BLOCK` records an independent prohibition; `INSUFFICIENT` records unresolved mandatory evidence.

## Scanner readiness and policies

Install the [separate pinned scanner environment](../tools/modelscan/README.md) and put its trusted executable on PATH **before launching** the workbench. Readiness is captured at startup; restart after changing the environment. Executables under model/workspace roots are excluded. A required scanner that is absent, disabled, timed out, skipped or unproven cannot complete coverage. A scanner subprocess is not a sandbox; OS network isolation is not guaranteed. macOS cannot provide required scanner memory-bound evidence, so applicable checks remain unresolved.

Custom policy import accepts bounded TOML, validates the existing policy schema, and pins private policy bytes. It never executes configuration. All admission decisions come from the Python engine; JavaScript displays evidence and explanations.

## Privacy, cancellation and recovery

The workspace uses owner-only directories/files and a single-owner lock. SQLite indexes jobs and report locations; pinned, validated report files remain authoritative. No automatic retention deletion occurs. Downloaded files follow browser/OS permissions and may contain sensitive filenames, metadata or raw evidence references. No telemetry, CDN, remote ingestion or public hosting is included.

Cancel through the visible scan control. Cancellation interrupts the own Python worker and cleans tracked scanner groups/snapshots; interrupted work cannot appear as a completed report. Closing a tab does not cancel a scan. Stop the service with Ctrl-C. On restart, unfinished jobs become **interrupted**, stale staging is cleaned, and reruns require an explicit action. Disconnected progress retains the last observed state until reconnection; it does not invent completion.

A second service using the same workspace fails with an owner conflict. Disk errors, invalid reports, pin mismatch and unsafe download IDs return controlled errors; do not delete locks while a service is active. After stopping the service, keep/move the whole workspace if preserving attachments. To remove history, explicitly remove the stopped service's workspace yourself; there is no hidden retention cleanup.

## Development and acceptance

```sh
npm ci --prefix frontend --ignore-scripts
uv run --extra ui python tools/workbench_schema.py --check
npm run --prefix frontend types
npm run --prefix frontend format:check
npm run --prefix frontend typecheck
npm run --prefix frontend test
npm run --prefix frontend build
cd frontend
npx --no-install playwright install chromium
npm run test:browser
```

From the repository root, `uv run --extra ui pytest -q` includes fresh installed-wheel UI acceptance when browser tooling is present; CI requires it. The current required CI rebuilds schema/types/assets and rejects drift on macOS 15 Intel. The browser suite measures 375/768/1024/1440 viewports, keyboard/reduced-motion behavior, hostile text escaping and automated accessibility rules. These checks do not substitute for a full human accessibility audit.

`tools/workbench_demos.py --out NEW_DIRECTORY` regenerates demonstrations using the static engine, refusing an existing target. Frozen run metadata records actual generation, and a manifest pins report bytes. Builds never silently regenerate reports. Actual verification results and distribution hashes are in [PROGRESS](PROGRESS.md); independent benchmark adjudication and PH-11 Linux/KVM loading are deferred outside this Mac preview; neither is required to use the local static product.

## Hugging Face URL scanning (local candidate)

Open **New scan → Hugging Face URL**, paste a model-repository URL such as `https://huggingface.co/hf-internal-testing/tiny-random-bert`, optionally select a branch/tag/commit, and review resource settings. Default browser transfer limits are 64 MiB per file and 128 MiB total. **Advanced scan settings** allows lower values or increases up to the fixed 1 GiB/file and 2 GiB total ceilings. Oversized files remain explicitly unassessed; a partial repository cannot approve. ModelVet resolves one immutable commit, inventories first, fetches files sequentially, and runs static checks without loading the model. Inspect **Hub retrieval** in the report for every omitted/failed path and required-check gap. JSON/Markdown includes the pinned source and all retrieval records. **Local folder** retains the existing rooted workflow.

Public models need no API key. For a private/gated model, configure your read-only HF_TOKEN in the environment before launching the server and explicitly enable its checkbox. ModelVet does not collect tokens in the browser. The checkbox is disabled when no local token is configured. Access denial, absent revision, network/size limits and scanner gaps remain explicit; none implies a successful assessment. You must already have access from Hugging Face. Current code uses a reviewed narrow stdlib transport and no third-party Hub dependency. This feature is in the working tree, not the previously published preview.
