# Reproducible safe examples

Run from the checkout after `uv sync --locked` with uv 0.13.3/Python 3.12.15. All generated bytes are synthetic. No example downloads or loads a model. Existing fixture paths are refused.

```sh
demo_root=$(uv run python -c 'import tempfile; from pathlib import Path; print(Path(tempfile.mkdtemp(prefix="modelvet-demo-")).resolve())')
uv run python examples/create_fixture.py "$demo_root/artifact"
uv run modelvet policy validate examples/default.toml --json
uv run modelvet scan "$demo_root/artifact" --out "$demo_root/reports" --json-summary > "$demo_root/summary.json"
report_rel=$(uv run python -c 'import json,sys; print(json.load(open(sys.argv[1]))["report"])' "$demo_root/summary.json")
uv run modelvet inspect "$demo_root/reports/$report_rel"
```

The clean synthetic case exits 0/APPROVE under the scoped default policy. This demonstrates format/claim/coverage/report behavior; it is not trained-model safety evidence. The summary's report path is relative to the output root you selected. Absolute host paths are redacted. Keep reports private: exact artifact filenames, policy owners and original raw scanner bytes may remain sensitive.

Create other cases with `--variant malformed` (30), `--variant unknown` (30), `--variant source` (20), or `--variant serialized` with `scan --scanner none` (30). These nonzero exits are assessment outcomes. Every case still produces JSON/Markdown when the report can be safely finalized. An invalid input/config is 40, a failure before a defensible report is 50, interruption is 130.

For CONTROLS/10, use `--policy examples/controls.toml`, which applies a MODEL_PRESENT isolation condition. See [POLICY_SPEC](../docs/POLICY_SPEC.md) for alternatives. Set an actual deployment owner. A named condition must be enforced by that owner; ModelVet does not provide deployment isolation.

## Scanner setup

ModelScan is optional to install, but mandatory when the format/policy requires it. Keep it outside the artifact in a separate environment because its dependency pins differ from core:

```sh
uv venv --python 3.12.15 .scanner-venv
uv pip sync --python .scanner-venv/bin/python --require-hashes --only-binary :all: tools/modelscan/requirements.lock
PATH="$PWD/.scanner-venv/bin:$PATH" uv run python tools/smoke_scanner.py
```

The real inert scanner smoke currently returns INSUFFICIENT on macOS: named pickle-file proof completes, while mandatory OS memory-bound evidence is unavailable. Linux execution is not verified locally. The external process is not a sandbox and OS network isolation is not enforced. No example enables model loading or PH-11 research.

## Semantic repeatability

Scan the same frozen fixture twice with the same effective policy/tools. Run IDs/timestamps change; `semantic_digest` stays equal. Source or snapshot changes before finalization produce failed identity and INSUFFICIENT. This is best-effort mutation detection, not an atomic filesystem snapshot or signed attestation.

## Offline advisory supplement

This example uses a deliberately synthetic advisory ID and invented package declaration. It is not a real vulnerability finding. Use a new fixture directory; the existing scan report is not edited.

```sh
umask 077
uv run python examples/create_fixture.py "$demo_root/advisory-artifact"
cp examples/advisory-environment.json "$demo_root/advisory-artifact/modelvet-environment.json"
uv run modelvet scan "$demo_root/advisory-artifact" --out "$demo_root/advisory-reports" --json-summary > "$demo_root/advisory-summary.json"
advisory_report_rel=$(uv run python -c 'import json,sys; print(json.load(open(sys.argv[1]))["report"])' "$demo_root/advisory-summary.json")
uv run modelvet advisories "$demo_root/advisory-reports/$advisory_report_rel" --snapshot examples/advisory-snapshot.json --as-of 2026-10-20T12:00:00Z > "$demo_root/advisories.json"
```

The final command exits 30 for the synthetic affected-version assertion. Omitting `--snapshot` also exits 30 because required advisory evidence is NOT_RUN. `--optional` permits unresolved evidence to exit 0 while keeping its status visible; positive matches still exit 30. There is no runtime network call. Read the [snapshot and matching contract](../docs/ADVISORY_SPEC.md) before supplying actual data. Preserve the snapshot privately; freshness/completeness/source claims are operator-supplied and not authenticated. This supplement does not recompute admission or establish exploitability.

## Verify, compare and batch stored reports

Continue from the first clean example above. These commands work after removing the original artifact. This example compares two scans of the same unchanged synthetic bytes; run timestamps differ while semantic content stays equal.

```sh
umask 077
uv run modelvet scan "$demo_root/artifact" --out "$demo_root/reports" --json-summary > "$demo_root/second-summary.json"
second_rel=$(uv run python -c 'import json,sys; print(json.load(open(sys.argv[1]))["report"])' "$demo_root/second-summary.json")
uv run modelvet verify "$demo_root/reports/$report_rel" > "$demo_root/verified.json"
uv run modelvet compare "$demo_root/reports/$report_rel" "$demo_root/reports/$second_rel" --fail-on-change > "$demo_root/compared.json"
uv run python - "$demo_root" "$report_rel" "$second_rel" <<'PY'
import hashlib, json, sys
from pathlib import Path
root = Path(sys.argv[1])
rows = [{"path": name, "expected_report_sha256": hashlib.sha256((root / "reports" / name).read_bytes()).hexdigest()} for name in sys.argv[2:]]
(root / "batch.json").write_text(json.dumps({"schema_version": "1.0.0", "reports": rows}))
PY
uv run modelvet audit-batch "$demo_root/batch.json" --root "$demo_root/reports" > "$demo_root/batch-audit.json"
```

All commands in this clean audit example return 0. Verification means declared stored bytes match; it does not authenticate authors or approve an artifact. Incomplete/pin-mismatched audits return 30. `compare --fail-on-change` returns 30 on semantic change. Manifest paths must be canonical, unique, relative to the explicit root; no discovery or model access occurs. Default output suppresses paths; digests can remain linkable. Keep the manifest and redirected output private. See [bounds and schemas](../docs/REPORT_AUDIT_SPEC.md).
